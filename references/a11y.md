# Canonical Accessibility (a11y) Standards: WCAG 2.1 AA Checklist

This reference defines accessible frontend architecture guidelines to ensure all user interfaces comply with WCAG 2.1 AA requirements.

---

## 1. Core Accessibility Principles (POUR)

1. **Perceivable**: Information and user interface components must be presentable to users in ways they can perceive (text alternatives, sufficient contrast, adaptable layouts).
2. **Operable**: Interface components and navigation must be operable via keyboard, switch device, or assistive technology without trapped focus.
3. **Understandable**: Information and operation of the user interface must be understandable (predictable behavior, clear error messages, consistent navigation).
4. **Robust**: Content must be robust enough to be interpreted reliably by a wide variety of user agents, including assistive screen readers.

---

## 2. WCAG 2.1 AA Audit Checklist

### Semantic Structure & Landmarks
- [ ] **Semantic Elements**: Use HTML5 landmarks (`<header>`, `<nav>`, `<main>`, `<aside>`, `<footer>`) instead of generic `<div>` containers.
- [ ] **Heading Hierarchy**: Exactly one `<h1>` per view; headings follow a sequential order (`<h1>` $\to$ `<h2>` $\to$ `<h3>`) without skipping levels.
- [ ] **Lists**: Bulleted items and collections use `<ul>`, `<ol>`, and `<li>`.
- [ ] **Buttons vs Links**: Actions that change state or trigger code use `<button type="button">`; navigation between pages uses `<a href="...">`. Never place `onClick` on a `<div>` without full keyboard handlers and ARIA roles.

### Keyboard Navigation & Focus Management
- [ ] **Tab Order**: All interactive controls are reachable via `Tab` and `Shift+Tab` in logical visual order.
- [ ] **Visible Focus Indicators**: Focus outlines are never removed (`outline: none` is forbidden unless replaced by an accessible custom ring).
- [ ] **Focus Trapping**: Modal dialogs, drawers, and overlay menus trap keyboard focus inside the modal while open, and restore focus to the triggering element upon close (`Esc` key closes modal).
- [ ] **Skip Links**: A "Skip to Main Content" link is present as the first focusable element on every page.

### Color Contrast & Typography
- [ ] **Normal Text Contrast**: Minimum contrast ratio of **4.5:1** between text and background.
- [ ] **Large Text Contrast**: Minimum contrast ratio of **3:1** for text $\ge 18\text{pt}$ (or $\ge 14\text{pt}$ bold).
- [ ] **UI Component Contrast**: Minimum contrast ratio of **3:1** for active user interface components (input borders, toggles, button boundaries).
- [ ] **Color Not Sole Indicator**: Information is never conveyed by color alone; always pair color with text labels, icons, or patterns.

### Forms & Error Handling
- [ ] **Explicit Form Labels**: Every `<input>`, `<textarea>`, and `<select>` has an associated `<label for="id">` or `aria-label`.
- [ ] **Help & Error Association**: Error messages are programmatically linked using `aria-describedby="error-id"` and flagged with `aria-invalid="true"`.
- [ ] **Required Fields**: Required inputs clearly marked visually and with `aria-required="true"`.

### Screen Reader & Dynamic Content (ARIA)
- [ ] **Image Alt Text**: Informative images include concise, descriptive `alt="..."`; purely decorative images use `alt=""` and `aria-hidden="true"`.
- [ ] **Live Regions**: Asynchronous status updates (toast notifications, streaming agent tokens) use `aria-live="polite"` or `role="status"`.
- [ ] **Icon Buttons**: Buttons containing only an SVG or icon must include an accessible name via `aria-label="Close dialog"` or visually hidden text (`sr-only`).

## 3. Automated a11y Verification Commands

```bash
# Run axe-core CLI accessibility audit
npx axe-cli http://localhost:3000 --tags wcag2a,wcag2aa

# Run Playwright accessibility scan
npx playwright test tests/a11y/
```
